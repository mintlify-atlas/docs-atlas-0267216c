---
title: Quickstart
description: Go from zero to your first error in Sentry in under five minutes.
---

This guide walks you through creating an account, setting up a project, installing an SDK, and viewing your first error in Sentry.

<Steps>
  <Step title="Create an account">
    Sign up at [sentry.io](https://sentry.io/signup/). You can also use GitHub or Google to authenticate.

    If you prefer to run Sentry on your own infrastructure, see [Self-hosted Sentry](/self-hosted) instead.
  </Step>

  <Step title="Create an organization and project">
    After signing in, Sentry prompts you to create an **organization**. Organizations are the top-level container for all your teams, projects, and data.

    Once inside, go to **Projects** and click **Create Project**. Select your platform, name the project, and click **Create Project**. Sentry generates a **DSN** (Data Source Name) for the project — you'll use this in the next step.

    <Note>
      The DSN looks like: `https://<public_key>@o<org_id>.ingest.sentry.io/<project_id>`

      You can always find it again at **Project Settings → Client Keys (DSN)**.
    </Note>
  </Step>

  <Step title="Install the SDK">
    Install the Sentry SDK for your language or framework.

    <Tabs>
      <Tab title="Python / Django">
        ```bash
        pip install --upgrade sentry-sdk
        ```
      </Tab>
      <Tab title="JavaScript / Node.js">
        ```bash
        npm install --save @sentry/node
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Configure the SDK">
    Initialize Sentry as early as possible in your application, before any other imports that might throw errors.

    <Tabs>
      <Tab title="Python (plain)">
        ```python
        import sentry_sdk

        sentry_sdk.init(
            dsn="https://<public_key>@o<org_id>.ingest.sentry.io/<project_id>",
            # Capture 100% of transactions for performance monitoring
            traces_sample_rate=1.0,
        )
        ```
      </Tab>
      <Tab title="Django">
        In your `settings.py`:

        ```python
        import sentry_sdk

        sentry_sdk.init(
            dsn="https://<public_key>@o<org_id>.ingest.sentry.io/<project_id>",
            # Set the environment so events appear under the right filter
            environment="production",
            # Associate errors with a release version
            release="my-app@1.0.0",
            traces_sample_rate=1.0,
        )
        ```

        The Django integration is activated automatically when `sentry_sdk.init` runs inside a Django project.
      </Tab>
      <Tab title="Node.js">
        ```javascript
        // instrument.js — import this file first, before anything else
        const Sentry = require("@sentry/node");

        Sentry.init({
          dsn: "https://<public_key>@o<org_id>.ingest.sentry.io/<project_id>",
          environment: "production",
          release: "my-app@1.0.0",
          tracesSampleRate: 1.0,
        });
        ```
      </Tab>
    </Tabs>

    Replace the `dsn` value with the one from your project settings.
  </Step>

  <Step title="Trigger a test error">
    Verify the integration is working by throwing a deliberate error.

    <Tabs>
      <Tab title="Python">
        ```python
        import sentry_sdk

        with sentry_sdk.push_scope() as scope:
            scope.set_extra("source", "quickstart")
            raise ValueError("This is a test error from Sentry quickstart")
        ```

        Or from a Django view:

        ```python
        def trigger_error(request):
            division_by_zero = 1 / 0
        ```
      </Tab>
      <Tab title="Node.js">
        ```javascript
        setTimeout(() => {
          throw new Error("This is a test error from Sentry quickstart");
        }, 99);
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="View the error in Sentry">
    Open the **Issues** page in your Sentry project. Within a few seconds you should see the test error appear with a full stack trace, request context, and any extra data you attached.

    From here you can assign the issue to a team member, set an alert rule, or mark it as resolved.
  </Step>
</Steps>
